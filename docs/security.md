# 安全与策略边界

## 风险分级

工具需声明副作用等级，并由代码侧策略执行，而非相信模型自报风险。

| 等级 | 示例 | 默认行为 |
| --- | --- | --- |
| `read` | mock web/knowledge search、calculator | 经输入校验后可自动执行 |
| `write` | 写入工作区文件 | 限定路径和大小；按策略确认 |
| `external` | mock email（未来可能接真实服务） | 显式确认；MVP 仅 mock |

对影响范围、可逆性或用户授权存在疑问时，采取更严格级别。路由置信度高不代表动作安全。

## Policy 要求

- 工具白名单由可信应用配置提供；Jev 不可添加工具或扩大权限。
- 低置信度、风险达到阈值、模型要求确认或工具要求确认时，不得自动执行。
- 确认应绑定 task、具体工具、参数摘要及过期时间；参数变化后必须重新确认。
- 预算耗尽、依赖超时、响应格式错误、概率缺失或状态不一致时，安全停止并留下可诊断 trace。
- 对重复请求和重试考虑幂等性；外部操作需要唯一操作标识和审计记录。

## 策略层的实现（当前代码）

- **风险下限优先于概率。** 工具声明为 `write` 或 `external` 时，策略引擎无条件返回 `ask_confirmation`，与 Jev 给出的风险分和置信度无关。概率阈值只对 `read` 类工具起作用。这条下限写在 `jev_router/policy.py` 一处，执行循环与评测都读同一份结论。
- **阈值可配置。** `PolicyThresholds` 经 `Settings` 与 `JEV_*_THRESHOLD` 环境变量注入，因此不同部署可以收紧而不必改代码；调低阈值等于放宽自动执行面，属于安全决策。
- **确认绑定参数与有效期。** 待确认项携带 `digest = sha256(task + action + arguments)[:16]` 与 `expires_at`；`POST /tasks/{id}/confirm` 必须回传同一个 `digest`，不符返回 `409`；超过 TTL（默认 900 秒）按未批准处理，运行以 `needs_confirmation` 结束。参数在确认后被重新合成也不会让旧批准生效，因为摘要变了。
- **API 鉴权是可选的强制项。** 未设置 `JEV_API_TOKEN` 时不鉴权并在启动时警告；设置后所有端点校验 Bearer token（`secrets.compare_digest`）。对外提供服务必须设置，并与「只绑回环地址」这一默认边界一起理解。

## 已知未覆盖

- 确认的审计记录只落在 trace 与 task 诊断里，没有独立的确认流水表。
- 没有速率限制与请求配额；滥用防护需要放在反向代理层。
- 阈值校准的结果需要人工判断是否采用，工具不会自动改写部署配置。


## 文件工具

`write_file` 只能写入明确配置的根目录下的相对路径。拒绝绝对路径、路径穿越、符号链接逃逸、超限文件和未授权覆盖。先验证规范化后的最终路径仍位于允许根目录内；不要将任意用户内容直接拼接为系统路径。

## 输入与模型输出

用户输入、搜索结果、工具输出和模型响应均视为不可信数据。provider 的概率与分数同样是数据：客户端只校验形状与归一化，不把概率当作授权依据。把内容作为数据传递，不允许其中的指令覆盖系统策略或工具权限。对工具参数按工具 schema 校验，并限制长度和资源消耗。

LLM 合成的工具参数同样不可信：resolver 原样返回模型输出，由工具自己的 pydantic 模型校验，`write_file` 的路径沙箱、`calculator` 的 AST 白名单和长度上限对它与手写参数完全一致。提示词中的参数说明从同一个模型派生（`Tool.input_model`），所以提示词无法广告一个工具会拒绝的字段。

## 凭证和日志

API key 仅从服务端环境或受控密钥存储读取。不得提交 `.env`、在前端暴露 key、把 Authorization header 或原始密钥写入 trace。Jev 与 LLM 的凭证遵循同一条规则：`LLM_API_KEY` 只存在于 API 进程，`x-api-key` header 不进 trace，store 的结构性保证同样适用（它只看得到 `RunResult`/`StepTrace`）。持久化用户目标和工具输入/输出前，应考虑敏感数据最小化、保留期限和访问控制；生产部署前定义删除与脱敏策略。

委托给 LLM 的提示词包含用户目标和历史结果，属于既有数据流：这些内容本来就已进入 Jev 请求 state 和 trace，新增的 LLM 调用不扩大暴露面，但 LLM 提供方因此成为另一个需要信任的接收方。

## 工具实现约束

- `ToolRegistry` 只接受可信代码预先构造的工具；模型输出不能注册工具或扩大可用集合。
- 工具应在入口严格校验输入并限制长度和资源消耗。`calculator` 只允许白名单 AST 算术节点，不执行 Python 表达式或代码。
- `web_search` 与 `send_mock_email` 当前只能使用本地 mock/fixture，不得建立外部网络连接。
- `write_file` 默认拒绝覆盖，只接受相对路径、限制 UTF-8 字节数，并将解析后的最终路径限制在配置根目录内；部署环境应避免其他进程并发篡改根目录中的符号链接。

## MVP 限制

`send_mock_email` 只产生本地模拟结果，不连接邮件服务。不开启任意 shell、任意 URL 抓取或未经许可的外部写操作。真实集成上线前需单独评估 SSRF、滥用、授权、审计和速率限制。
